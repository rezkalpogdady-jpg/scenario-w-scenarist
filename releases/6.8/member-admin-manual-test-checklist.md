# قائمة الاختبار اليدوي لصلاحيات العضو والمدير — إصدار 6.8

> الغرض: توثيق سيناريوهات التحقق قبل اعتبار ملفات الأعضاء ومكتبة السيناريوهات ولوحة الإدارة جاهزة.
> الحالة الحالية: **قائمة اختبار فقط — لم تُنفذ على Supabase أو متصفح حي بعد**.
> لا تستخدم بيانات شخصية حقيقية أو ملفات حساسة أثناء الاختبار. استخدم حسابات وملفات تجريبية.

## حسابات الاختبار المطلوبة
- [ ] زائر غير مسجل (anon).
- [ ] عضو A بحساب مستقل وبريد مؤكد.
- [ ] عضو B بحساب مستقل وبريد مؤكد لاختبار منع الوصول بين الأعضاء.
- [ ] مدير معتمد، مع إثبات أن دور المدير مضبوط في app_metadata من مسار الإدارة الموثوق.
- [ ] لا تستخدم حساب المدير كبديل لاختبار صلاحيات العضو.

## 1. التصفح العام — anon
- [ ] يستطيع الزائر فتح الصفحات العامة دون إنشاء حساب.
- [ ] لا تظهر بيانات الملف الشخصي المعلّقة أو المرفوضة.
- [ ] لا تظهر أعمال الأعضاء المعلّقة أو المرفوضة.
- [ ] لا يستطيع الزائر قراءة ملفات member-submissions الخاصة أو إنشاء Signed URL لها.
- [ ] لا يستطيع الزائر فتح سيناريو PDF غير منشور أو طلب رابط ملفه.
- [ ] تظهر فقط سجلات site_content المنشورة والمسموح بعرضها.
**النتيجة المتوقعة:** قراءة المحتوى العام المنشور فقط، دون بيانات أو ملفات خاصة.

## 2. إنشاء العضوية والملف الشخصي — عضو A
- [ ] إنشاء حساب بالبريد وكلمة المرور وتأكيد البريد.
- [ ] تسجيل الدخول واستعادة كلمة المرور.
- [ ] حفظ ملف شخصي تجريبي بالحقول المسموح بها.
- [ ] تكون حالة الملف الجديدة pending على الخادم، حتى لو حاول العميل إرسال حالة مختلفة.
- [ ] يستطيع العضو قراءة ملفه وتعديله وفق الأعمدة المسموح بها.
- [ ] لا يستطيع العضو تغيير profile_status إلى approved أو تعديل حقول إدارية.
- [ ] بعد تعديل بيانات جوهرية في ملف معتمد، تعود الحالة إلى pending إذا كان Trigger المطلوب مثبتًا ومفعّلًا.
- [ ] لا يظهر الملف في الدليل العام قبل موافقة المدير.
**النتيجة المتوقعة:** ملكية ذاتية للملف، وحالة مراجعة لا يتحكم فيها العضو.

## 3. عزل بيانات الأعضاء — عضو B
- [ ] يحاول عضو B قراءة ملف عضو A مباشرة باستخدام معرفه.
- [ ] يحاول عضو B تعديل ملف عضو A.
- [ ] يحاول عضو B حذف ملف عضو A.
- [ ] يحاول عضو B قراءة سجل عمل عضو A أو تنزيل ملفه الخاص.
- [ ] يحاول عضو B اعتماد ملف أو عمل عضو A أو تغيير حالته.
- [ ] يعاد الاختبار باستدعاء مباشر من عميل Supabase، وليس من واجهة الموقع فقط.
**النتيجة المتوقعة:** تُرفض كل محاولة وصول أو تعديل خارج ملكية العضو، وتُفرض النتيجة بواسطة RLS/الصلاحيات على الخادم.

## 4. رفع أعمال الأعضاء
- [ ] يرفع عضو A ملف PDF تجريبيًا صالحًا ضمن الحد المسموح.
- [ ] يرفض النظام امتدادًا غير مسموح أو ملفًا فارغًا أو زائد الحجم.
- [ ] يُحفظ الملف في bucket الخاص member-submissions بمسار مرتبط بهوية المالك.
- [ ] لا يستطيع عضو B أو anon تنزيل الملف أو إنشاء Signed URL له.
- [ ] لا يظهر العمل في المكتبة العامة قبل الموافقة.
- [ ] بعد اعتماد المدير، يظهر العمل المنشور فقط وفق مسار النشر المقصود.
- [ ] عند الرفض، يظل العمل غير منشور ولا يصبح الملف الخاص عامًا.
**النتيجة المتوقعة:** رفع خاص ومراجعة إدارية قبل النشر، مع تحقق التخزين من هوية المالك.

## 5. صلاحيات المدير والمراجعة
- [ ] يستطيع المدير المعتمد تحميل قائمة الملفات الشخصية المعلقة/المرفوضة.
- [ ] يستطيع المدير اعتماد ملف عضو A أو رفضه عبر RPC المعتمد.
- [ ] يستطيع المدير مراجعة أعمال الأعضاء واعتمادها أو رفضها.
- [ ] بعد الاعتماد، يعاد تحميل قائمة المراجعة والمحتوى العام وتظهر الحالة الصحيحة.
- [ ] يحاول عضو عادي استدعاء RPC الخاص بالمراجعة مباشرة.
- [ ] يحاول anon استدعاء RPC الخاص بالمراجعة مباشرة.
- [ ] تُرفض محاولات غير المدير حتى عند تجاوز الواجهة واستدعاء RPC مباشرة.
- [ ] تُراجع تعريفات RPC ومالكها وSECURITY DEFINER/INVOKER وsearch_path وامتيازات EXECUTE قبل اعتماد النتيجة.
**النتيجة المتوقعة:** قرار المراجعة مقصور على مدير موثوق على مستوى قاعدة البيانات، وليس مجرد إخفاء أزرار الإدارة.

## 6. مكتبة السيناريوهات وملفات PDF
- [ ] يضيف المدير سجل سيناريو وملف PDF تجريبيًا.
- [ ] يبقى السجل غير المنشور غير ظاهر للعضو.
- [ ] بعد النشر، يظهر السجل المنشور للأعضاء المسجلين فقط وفق السياسة المعتمدة.
- [ ] يحصل القارئ على Signed URL مؤقت بدل رابط عام دائم.
- [ ] لا يستطيع anon فتح الملف.
- [ ] لا يستطيع عضو تغيير published أو حذف السجل.
- [ ] لا يحذف النظام ملف Storage ما زال مرتبطًا بسجل آخر.
- [ ] تفشل القراءة بشكل واضح وآمن عند غياب الجدول أو bucket أو الصلاحية.
**النتيجة المتوقعة:** بيانات منشورة فقط، وقراءة محمية، وروابط ملفات مؤقتة.
