# مراجعة فنية احترافية – منصة سيناريو وسيناريست
التاريخ: 2026-11-08
الفرع: `stage/6.6-platform-audit`
الأساس: أحدث `main` مع حفظ حزمة 6.5 دون دمجها في الإنتاج.

## 1) ما تم التحقق منه مباشرة
- المستودع يحتوي على واجهة رئيسية واحدة `index.html` مع README وسير نشر GitHub Pages.
- حجم الواجهة الرئيسية التي تمت مراجعتها: 169,248 حرفًا، ونسخة 6.5 المحفوظة مطابقة لها في SHA عند نقطة المزامنة.
- يوجد تكامل Supabase من الواجهة باستخدام مفتاح `sb_publishable_` فقط؛ لم يظهر مفتاح `service_role` في المقطع المفحوص.
- المحتوى العام يُقرأ من جدول `site_content` مع شرط `published = true` ثم يوزع حسب `content_type`.
- لوحة الإدارة تسمح برفع صورة/فيديو/صوت/PDF/Word إلى bucket باسم `site-media`، وتخزين رابط المحتوى وبياناته.
- الأكاديمية تعرض منهجًا من 30 عنوانًا، وتربط المادة المنشورة بعنوان المحاضرة المطابق؛ مشغل الفيديو يدعم ملفات مباشرة وHLS وبعض روابط YouTube/Vimeo.
- مكتبة السيناريوهات تستقبل عناصر من نوع `library` وتعرض رابط الملف.
- الراديو والتليفزيون لديهما مشغلات HTML5 ودعم HLS، لكن مصفوفتَي المحطات والقنوات تبدأان فارغتين، ولا يظهر محتوى فعلي قبل إضافة سجلات منشورة من الإدارة.
- إرسال أعمال الأعضاء يستخدم bucket خاصًا `member-submissions` وحدًا في الواجهة قدره 25 MiB، مع أنواع PDF وDOC وDOCX وTXT.
- هناك جداول/وظائف مستخدمة في الواجهة تشمل `member_profiles` و`member_works` و`idea_submissions` و`chess_games`، بالإضافة إلى RPC لمراجعة أعمال الأعضاء.

## 2) الفجوات التي تمنع اعتمادًا احترافيًا الآن
1. **غياب مخطط قاعدة البيانات الأساسي عن المستودع:** لا توجد ملفات SQL تأسيسية ظاهرة في شجرة الملفات الحالية. لذلك لا يمكن اعتماد Migration 6.5 أو تعديل الجداول بأمان دون مطابقة أسماء الأعمدة والسياسات والدوال الموجودة فعليًا.
2. **تخزين وسائط الإدارة غير موثق داخل المستودع:** الكود يتوقع bucket باسم `site-media` ويستخدم `getPublicUrl`، لكن لا توجد وثيقة تأسيس/سياسات واضحة له ضمن الملفات الحالية.
3. **الراديو والتليفزيون جاهزان كواجهة ومشغل فقط:** لا توجد محطات/قنوات مضافة تلقائيًا، ويجب أن تكون المصادر رسمية ومصرحًا بإعادة تشغيلها أو تضمينها.
4. **الأكاديمية ليست نظام إدارة تعلم كاملًا بعد:** يوجد فهرس عناوين وربط بمحتوى `site_content`، لكن لا يظهر نموذج مستقل للواجبات والتقدم والاختبارات وشهادات الإكمال.
5. **المكتبة تحتاج دورة حياة للسيناريو:** لا يظهر في الواجهة العامة قارئ PDF مدمج موحد أو نموذج إصدار/نسخ/مراجعة مفصل للسيناريوهات؛ العرض الحالي يعتمد على رابط الملف.
6. **اختبارات التشغيل الحية غير متاحة من هذا الاتصال:** لم يتم الدخول إلى مشروع Supabase أو تجربة حسابات فعلية أو رفع/تشغيل ملفات وبث حقيقي.
7. **اختبارات النشر محدودة:** سير GitHub Pages الحالي ينشر `main` عند الدفع إليه، ولم يتم تنفيذ نشر أو تغيير إعدادات الإنتاج.

## 3) قرار الحماية والإصدار
- لم يتم دمج أي فرع في `main`.
- لم يتم تشغيل SQL على Supabase.
- لا تُعد مراجعة 6.5 اعتمادًا أمنيًا نهائيًا قبل مطابقة Migration مع مخطط القاعدة الحي وتجربة أدوار زائر/عضو/مدير.
- يجب الاحتفاظ بنسخة احتياطية قبل أي تعديل على قاعدة البيانات أو نشر الإنتاج.

## 4) ترتيب التطوير المقترح
### المرحلة A – تثبيت الأساس
- استخراج/استعادة مخطط Supabase الفعلي وحفظه في المستودع كملف SQL موثق، مع عدم تضمين أسرار.
- مراجعة RLS لكل جدول وسياسات Storage ودالة مراجعة أعمال الأعضاء.
- إضافة فحوصات آلية للملفات (JavaScript syntax، فحص أسرار، فحص مسارات وروابط الوسائط) ضمن GitHub Actions.
- اختبار تسجيل الدخول واستعادة كلمة المرور وأدوار العضو والمدير.

### المرحلة B – نظام وسائط موحد
- تعريف أنواع المحتوى وحقول الوسائط بوضوح: ملف مرفوع، رابط خارجي، نوع MIME، الحجم، حالة النشر، مالك المحتوى، وبيانات الترخيص/المصدر.
- التحقق من النوع والحجم على الواجهة والخادم/Storage، وليس على الواجهة فقط.
- التعامل مع فشل رفع الملف أو فشل حفظ السجل دون ترك ملفات يتيمة.
- فصل الملفات الخاصة عن العامة وعدم استخدام روابط عامة لملفات الأعضاء.

### المرحلة C – الأكاديمية ومكتبة السيناريو
- دعم فيديو ومحاضرة مكتوبة وملفات مرفقة لكل درس.
- إضافة ترتيب الدروس والواجبات والتقدم والاختبارات تدريجيًا.
- قارئ PDF داخل الموقع مع صلاحيات قراءة واضحة، وبيانات المؤلف والنسخة والتصنيف وحالة المراجعة.
- اعتماد كل مادة قبل نشرها، وتسجيل تاريخ التعديل وصاحب التعديل.

### المرحلة D – الراديو والتليفزيون
- لوحة إدارة للمحطات والقنوات تشمل الاسم والتصنيف والشعار والرابط ونوع البث ومصدره وحالة التحقق والترخيص.
- فحص صيغة الرابط وتوافق HLS/MP3/MP4 وقيود CORS/التضمين قبل إظهار زر التشغيل.
- رسائل واضحة عند توقف المصدر، وإيقاف المشغل السابق عند الانتقال لمحطة أخرى.
- عدم إضافة بث غير رسمي أو محتوى لا يسمح مصدره بالتضمين.

## 5) بوابة قبول كل إصدار
لا يعتبر الإصدار جاهزًا إلا إذا:
- اجتاز فحص الصياغة الآلي.
- لم يحتوِ أسرارًا أو مفاتيح خادم.
- اجتاز اختبارات RLS للزائر والعضو والمدير.
- نجح رفع/قراءة/حذف الملف وفق الصلاحية.
- نجح اختبار تشغيل وسائط حقيقية مرخصة على هاتف Android ومتصفح سطح المكتب.
- حُفظت نسخة احتياطية وسجل تغييرات، ولم يتغير `main` إلا عبر مراجعة واعتماد واضحين.
